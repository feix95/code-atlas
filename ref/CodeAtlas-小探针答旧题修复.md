# 需求表:小探针答旧题修复(历史问答按"轮"配对)

> 状态:已拍板,待施工(大锤,单独一锤一 commit)
> 来源:2026-09-18 小葵报案"llm 还是没法识别哪条发言是最新的,甚至无视我最新的问题,回答之前的问题"
> 上回修过一次(commit 2df505b,历史窗口改成从尾部取最近 3 对完整问答),方向没错但没修到根 —— 这次查明了:窗口方向是对的,**窗口里装的历史内容本身是脏的**

## 一、病根(三层叠加,精确到代码)

### 主犯:渲染层按"条"收历史,不管"轮"有没有答完

`src/renderer/src/useAiChat.ts` 的 `buildHistory()`(约 81-88 行)逐条过滤:note 扔、非 done 扔,剩下的 user/assistant 全部入史。问题在于——

- **user 消息一发出就永久是 `done`**(send 里写死),哪怕这一轮的回答**报错、超时、被点"停一停"**,这条问题照样入史;
- 它对应的 assistant(state = error/cancelled)被过滤掉 → 历史里留下一道**"问了但从没被回答"的悬空旧问题**;
- 下一轮正常问答完成后,这道悬空问题**沉到历史中间**,从此**每一轮请求都带着它**。

### 帮凶:主进程只收拢窗口两头,不摘中间的悬空

`src/ai/index.ts` 的 `sanitizeHistory()`(约 145-147 行)只处理窗口**开头**的孤立 assistant 和**结尾**的悬空 user。**沉到中间**的悬空旧问题没人管。

### 二帮凶:合并逻辑把悬空旧问题和下一问粘成一条

`src/ai/index.ts` 的 `mergeConsecutiveMessages()`(约 321-332 行)把相邻同角色消息合并。悬空旧问题 u2 和下一个正常问题 u3 相邻 → 粘成"u2\n\nu3"一条。模型看到:**用户连问两件事,却只有一条回答**——小模型的第一反应就是补答那条没被回答的**旧问题**。这就是"无视我最新的问题,回答之前的问题"的精确机制。

### 从犯:重试按钮让同一问题反复入史

`src/renderer/src/components/FreeChatPanel.tsx` 的 `retryFrom()`(约 358-371 行)重试 = 把旧问题原样再 send 一遍,旧的问答对(含失败轮)**原样留在列表里**。同一问题在历史里出现两次,形态进一步混乱。

### 为什么上回修了还犯

上回(commit 2df505b)修的是"窗口取哪一头"(从头取→从尾取),自测断言的历史都是干净的完整问答对。这次犯的是**窗口里的内容带着没被回答的旧问题**——两个不同的病,共用一个症状。报错轮在本地小模型场景是家常便饭(上下文挤爆、超时、断连),所以悬空问题几乎每场对话都在攒。

## 二、修复方案(三刀,建议一锤做完)

### 刀一(治本):渲染层历史改按"轮"成对收集

- `buildHistory()` 重写:**从后往前,把"回答 + 它前面最近的提问"配成一对,只收回答是 done 的完整轮;提问找不到 done 回答的,整轮扔掉**(不管它在中间还是结尾)。
- **重复问题天然去重**:按上述配对法,重试场景里旧的失败轮没有 done 回答、整轮被扔;若旧轮回答是 done(半截话带注脚那种),相邻两对提问内容相同时**只留最新一对**。
- 纯逻辑搬进 `src/shared/`(新建如 `src/shared/chatHistory.ts`),渲染层与自测脚本共用同一份口径——项目惯例(compact.ts 就是这么干的),自测脚本拖得进来秒跑。

### 刀二(兜底):主进程 sanitizeHistory 加中间扫描

- 现有"两头收拢"照旧;新增**中间扫描:连续多条 user 只留最后一条**(前面几条都没有紧邻的回答,必是悬空;最后一条才是刚聊完被回答的)。
- 清洗完的不变式(写进自测断言):**开头必是 user、结尾必是 assistant、任意相邻两条必不同角色**。

### 刀三(注意力锚):给当前问题挂显式标牌

- 历史清干净后,形态就是 `[..., 旧问, 旧答, 当前问题]`,但当前问题后面粘着联网资料、参考资料指路话(设计如此),历史里的旧问题反而是"干净短句"——小模型按"长得最像待答问题"作答就会偏。给当前问题加一行前缀锚点,常量导出(如 `CURRENT_QUESTION_PREFIX`),内容类似:
  `(用户本轮提出的新问题,回答以下这条;早前问答都只是历史背景)`
- **同步动作**:`src/main/index.ts` 里 agent 链取 `currentQuestion` 的逻辑(约 1073-1080 行)要剥掉这个前缀,免得工具轮的提醒卡变成"提醒:(以下是新问题…)真问题"的自指冗余。

### 明确不动的东西

- **agent 工具循环、提醒卡机制不动**——提醒卡每轮把当前问题钉在模型眼皮底下,本来就是防答旧题的正确设计。
- **窗口大小不动**(渲染层 8 条、主进程 6 条收拢成 3 对)——治的是"内容脏",不是"窗口方向"。
- 聊天记录仍只在内存,不落盘。

## 三、验收标准

### 自测断言(scripts/selftest-ai.mts,注意传参跟紧签名改动)

- [ ] 成对收集:given `[u1, a1, u2(无回答), u3, a3]` → 输出不含 u2,其余原样
- [ ] 报错轮:given `[u1, a1, u2, a2(state=error), u3, a3]` → 输出不含 u2、不含 a2
- [ ] 取消轮:given `[u1, a1, u2, a2(state=cancelled), u3, a3]` → 同上
- [ ] 重试轮:given `[u1, a1, u2, a2(done半截), u2, a2'(done), u3, a3]` → u2 只出现一次,配的是最新的 a2'
- [ ] 主进程兜底:`sanitizeHistory([u1, u2, a2, u3, a3])` → 连续 user 只留最后一条 → `[u2, a2, u3, a3]`
- [ ] 不变式:任意乱序脏输入,清洗后开头必 user、结尾必 assistant、相邻必不同角色
- [ ] 端到端:`buildFreeChatMessages` 输出的最后一条 user 是当前问题(带锚点前缀);agent 链 `currentQuestion` 提取后不含锚点前缀
- [ ] `typecheck` / `lint` / `test` / `build` 全绿

### 实测清单(小葵手工,一条一条来)

- [ ] 问一个问题,探针答到一半点"停一停",紧接着问新问题 → 答**新问题**,不补答被停那轮的
- [ ] 制造一轮报错(比如把模型上下文调到最小、问个长问题),再问新问题 → 答**新问题**
- [ ] 点一次"重试",等它答完,再问新问题 → 答**新问题**
- [ ] 连聊 10 轮以上,突然问"我最新问你的问题是什么" → 能准确复述最新那条
- [ ] 开着"翻文件模式"重复上面前两条 → 同样答新问题
- [ ] 以上全过之后,Developer 日志里抽查两轮:历史块里不再出现"问了没答"的孤儿问题

## 四、边界与不做的事

- 不做历史持久化(记录仍在内存,"新对话"清空即真没了,定位不变)。
- 不给历史窗口加长——3 对够垫底,上下文留给附件和本轮问题。
- 9B 小模型即使历史全干净,偶尔仍可能犯迷糊;本锤治的是**结构性误导**(每轮都带着"没被回答的旧问题"在勾它),结构清干净后若还有零星走神,再单独评估要不要加强提示词,不在本锤范围。
