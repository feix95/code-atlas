# 需求表：划词问一问（二期候选，未排期）

> 状态：**二期候选**——需求方向已聊通，细节未拍板，未排期。开工前需过一遍第五节的开放问题
> 来源：2026-09-18 灵感窗口讨论
> 排期：排在《CodeAtlas-面板收起与桌宠托管》《CodeAtlas-右键问一问》都落地之后

## 一、为什么做（定位）

原始想法：**在任意软件里选中一段文字 → 右键"问问小探针"** → 桌宠弹气泡，选中的文字直接带进去问。

为什么它是二期、机制还和右键问一问不同：

- 文本选中后的右键菜单是**各个软件自己画的**（记事本、浏览器、VSCode 各画各的），外部程序**塞不进去**——资源管理器那套注册表路线在这里行不通。
- 真能落地的路线是：**全局热键触发 → 模拟 Ctrl+C 抓取当前选中的文字 → 桌宠弹气泡**。这是一套完全不同的机制，独立一锤。

## 二、需求明细（草案）

### 2.1 触发

- 全局热键（默认键位开工前定，候选如 `Alt+Q`；在设置页可改、可关）。
- 只在 CodeAtlas 运行期间生效（含收起/桌宠模式）。

### 2.2 抓取

- 热键触发时模拟 Ctrl+C，从当前活动窗口抓取选中文本。
- **剪贴板礼貌原则**：抓取前备份用户剪贴板原内容，抓完恢复原样——绝不能因为问了小探针一句，把人家复制着的东东弄丢。
- 抓不到（当前没选中任何文字）：不弹空泡，具体行为见开放问题第 1 条。

### 2.3 气泡

- 桌宠弹对话气泡，抓到的文字作为**引用块**附在输入框（可删可改），用户补一句问题就发送。
- 脑与右键问一问同源：复用自由聊天后端，换皮不换脑。

## 三、验收标准（草案，开工前随开放问题一起细化）

- [ ] 任意程序里选中文字按热键，桌宠弹气泡，选中文本已带入引用块
- [ ] 用户剪贴板原内容在抓取后原样还原（复制一段话 → 划词提问 → 再粘贴，粘出来的还是原来那段）
- [ ] 没选中文字按热键：不误触发、不弹空泡（具体行为按开放问题第 1 条拍板后写死）
- [ ] 热键可在设置页修改和关闭；关闭后不再全局拦截
- [ ] `typecheck` / `lint` / `test` / `build` 全绿
- [ ] 125% 缩放复查气泡显示与输入热区

## 四、边界与不做的事

- **不做**浏览器扩展（那是另一条产品线，违背轻量定位）。
- **不做**后台常驻监听剪贴板（只在热键触发那一刻才碰剪贴板，平时绝不偷看）。
- 热键冲突不硬抢：注册失败（被其他软件占了）就在设置页黄字说明，不静默失效。

## 五、开放问题（开工前必须逐条拍板）

1. **没抓到选中文本时的行为**：完全无反应（最省心）vs 气泡提示"没抓到选中的文字"（更清楚）。哥倾向前者——不弹窗不打扰，符合"当它不存在"的定位。
2. **默认热键选哪个**：要避开常用软件（Alt+Tab、Win 系、微信/QQ/QQ截图、输入法切换）。开工前列一张候选表实测。
3. **抓取兼容范围**：模拟 Ctrl+C 在浏览器、Electron 应用、常规编辑器都好使；个别软件（如终端、某些全屏游戏）会失灵。第一版明确"主流场景可用"，不承诺全软件覆盖。
