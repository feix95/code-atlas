# UI 框架 · 工作台改造方案(待小葵审定后施工)

> 定位:把「UI 框架」页签从功能页面改造成编辑软件式工作台——底板是主角,零件和工具在手边。
> 依据:小葵 2026-10-03 口述「空白底板 + 零件工具在手边」+ 规格 第 5.3 节 布局图(左栏导航一直没落地)。
> 与规格的关系:本方案是 第 5.3 节 的迟来落地 + 把 M3「底板即屏」的壳提前;不改变 M1 已验证的数值管线。

## 1. 现状问题(为什么看不懂)

- 页签只占内容区,左侧全局侧栏还挂着当前项目的文件树——与工作台无关,是观感混乱的第一来源。
- 画布首屏是「组件墙」零件矩阵,落点是「设计系统目录」视角,不是「我的 app」视角。
- 工具条堆了 12+ 个控件,术语是工程黑话(规范/变量板/适配器)。
- 「风格预设」只在起步页选一次,画布里无入口;「导出给 AI 用」这条产品意义链在界面上没有任何说明。

## 3. 落法(逐项)

### 3.1 侧栏换脸(占掉文件树那块)

- 沿用 `settingsMode` 先例(`useSettingsNav.ts` + `WorkspaceSidebar.tsx`):激活签 `kind === 'uiframe'` 时,侧栏中段换成零件盒,文件树 `display:none` 保活不卸载,切回来原样还在。
- 侧栏收起态沿用同一逻辑:进 UI 框架签时收着就掀开,走时还原。
- 零件盒从 schemeStore/docStore 取数(模块级单例,不受挂载位置影响)。

### 3.2 零件盒内容(第 5.3 节 左栏落地)

| 区块     | 内容与行为                                                                                                                              |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| 组件     | 9 组件清单(图标 + 名字);点击 → 画布切「零件墙」并滚到该组件节。M3 起支持拖上底板                                                        |
| 变量     | 变量分组折叠(颜色/字号/间距/圆角/阴影/控件尺寸);点击组 → 画布切「变量板」并定位该组                                                     |
| 风格     | 4 个内置风格卡(第 8.2 节 中已实现的 4 个);**一键套用**:把该模板对应风格预设的变量组覆盖到当前 doc(进撤销栈,可 Ctrl+Z 回退),方案身份不变 |
| 图标     | 当前方案已用图标槽位清单 + 「换图标」入口(复用现有 IconPicker);完整浏览器(分类/中文搜索)归 M3                                           |
| 我的方案 | 库清单缩略图卡(复用 SchemeCard),点击开方案                                                                                              |

### 3.3 底板视图

- 画布新增第 4 视图 `bench`(底板),**设为默认视图**。
- 内容:模板起步 → 平台示例页躺在设备框里;空白起步 → 设备框内只有空态提示(「从左边组件里挑一个放上来——自由摆放 M3 开放」)。
- 底板上的部件沿用现有 `data-uf-part` 点选 + 手柄拖动调数值,所见即所导出的管线不变。
- 原「示例屏」并入底板,不再单列;「组件墙」更名「零件墙」保留为查看入口。

### 3.4 工具条瘦身与去黑话

| 现在                             | 改成                                                                  |
| -------------------------------- | --------------------------------------------------------------------- |
| 「规范」chip                     | 「检查」chip(计数徽标不变)                                            |
| 「导出规格包」                   | 「导出给 AI」主按钮;点开导出成功横幅里写明「把这个文件夹交给你的 AI」 |
| 「复制主题」下拉                 | 收进「导出给 AI」旁的次级菜单                                         |
| 视图 seg「组件墙/变量板/示例页」 | 「底板/零件墙/变量板」                                                |
| 起步页                           | 加一行产品说明:「调好数值 → 导出给 AI → 照着做一模一样的界面」        |

### 3.5 不动的部分

- docStore/schemeStore 数据层、导出管线、体检、平台校验、IPC——零改动。
- 底板内容仍是「生成的文档」;把屏做成方案数据(可增删组件)是 M3 工作,本方案不碰。

## 4. 边界与取舍(照实标注)

- **空白起步后底板是空的且还不能往上放东西**——M3 才补拖放。空态必须有提示和「一键载入示例内容」的出口,不能是死屏。
- 「风格一键套用」覆盖的是 tokens + icons;页面变量组(各平台页变体选择)不动,已在方案里的微调会被模板值覆盖——这属于「换风格」的预期语义,依赖撤销栈兜底。
- 分屏时零件盒跟随激活签换脸(与设置导航同规则);单例签只有一个实例,不存在两个底板抢一份零件盒的问题。
- 「图标」区块本期只列已用槽位,完整图标浏览器是 M3 的活,不做进这次。

## 5. 验证

- typecheck/lint/test/build/journey 全链。
- journey 新增:UI 框架签激活 → 侧栏变零件盒、文件树隐藏;点组件跳零件墙对应节;点风格套用后变量变;底板为默认视图;空白起步见空态提示。
- 自测:本里程碑几乎纯界面壳,数据层不变,现有 61 项自测应零回归。

## 6. 明确不做(本里程碑)

- 底板上自由摆放/增删组件(M3)。
- 图标完整浏览器(M3)。
- 风格预设清单从 4 个扩到 9 个(第 8.2 节 补齐,随 M3 或单开)。
- 问卷相关一切(M2 独立)。
