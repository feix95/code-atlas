## 1. 产品定义

### 1.1 一句话定位

让不会写代码的人,通过**选择题**定下 app 的立项条件,通过**可视化拖拽**定下 app 的全部 UI 数值,最后导出一份**任何 AI agent 都能按数值精确复刻**的规格包【给定 + AI补充措辞】。

### 1.2 要解决的问题【给定】

1. 用户无法把 UI 设计构想精确传达给执行的 AI agent。
2. 已尝试的方法精度不足:截图后手改 < 让 AI 先出 HTML 再照着改;但 agent 仍不会百分百复刻,倾向"差不多就收工"。
3. 要逼近百分百,只能对着真实 app 让 agent 反复改细节,极其耗费心力。
4. 而「产品立项 → 技术选型 → UI 大体(版式 / 美术风格 / 框架)→ 框架内新增功能 + 微调 → app 雏形」这条流程本身是可以稳定固定下来的。

### 1.3 核心思路

1. **数值先行**:UI 的全部数值独立成一份规格,不直接挂钩任何真实 app 的代码【给定】。
2. **可视化调控**:数值在 CodeAtlas 内渲染成真实的线框、按钮、样式;用户拖动边、角、位置即修改数值【给定】。
3. **所见即所导出**:画布上的组件由一份 HTML + CSS 变量渲染,导出时交付的就是这同一份代码与变量,agent 只需搬运,不需要理解和重新发挥【AI补充】。原因:SVG 能被精准复刻,本质是它就是图形的源码;规格包沿用同一原理。
4. **流程可控、可选、可调**:每一步都可以跳过、回改、保存【给定】。

### 1.4 目标用户【AI补充】

| 优先级 | 用户                                     | 典型诉求                                          |
| ------ | ---------------------------------------- | ------------------------------------------------- |
| 主     | 用 AI coding 做 app 的非程序员(小葵这类) | 从零开始,把想法变成 agent 能精确执行的规格        |
| 次     | 会写代码的独立开发者                     | 快速定一套 UI 规格,省掉设计稿环节                 |
| 再次   | 已有 app、想重整 UI 的用户               | 把现有 app 的数值导入进来调整,再交给 agent 统一改 |

### 1.5 产品边界与只读契约【给定 + AI补充】

- CodeAtlas **从不修改用户的任何项目文件**。
- 文件写入仅限两处:① 用户主动「导出」时写到用户自选的位置;② 应用数据目录内的「我的方案」库(属于用户主动保存的功能本体,与模型货架同类,不属于无意义缓存)。
- 联网仅在用户主动操作时发生(社区浏览 / 上传 / 下载、内置 agent 联网查证),沿用 CodeAtlas「联网默认关」原则。

## 4. 技术栈对 UI 数值的影响(定性结论)【AI补充,回应小葵「需帮我做这个判断」】

**结论:设计数值本身与技术栈无关;技术栈只影响单位写法、导出代码形式与平台规范三件事。**

| 影响点       | 具体差异                                                                                                                                      | 本功能的处理                                                                      |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| 单位         | 网页类用 rem / px;Android 用 dp(尺寸)与 sp(字号);iOS 用 pt;Flutter 用逻辑像素;React Native 写无单位数字。1 倍屏下均等于 1 逻辑像素,可精确互换 | 内部统一存逻辑像素,界面与导出按目标换算显示;网页类目标默认显示 rem(第 12 节)      |
| 导出代码形式 | 网页类导出 CSS 变量 / Tailwind 主题;Flutter 导出 ThemeData;SwiftUI / Compose 各有写法                                                         | 每种技术一个导出适配器(第 13.5 节),新增技术只加适配器                             |
| 平台规范     | 手机:最小点击区、安全区、无悬停态;电脑:有悬停态与键盘焦点、窗口标题栏、信息密度更高                                                           | **平台**决定画布外框、模板与校验规则(第 5.7 节);**技术栈**到导出时再选,可随时更换 |

**精度分级(照实标注,不夸大)**

| 导出目标                                                              | 精度            | 原因                                            |
| --------------------------------------------------------------------- | --------------- | ----------------------------------------------- |
| 网页家族(HTML / CSS、React / Vue / Svelte、Electron、Tauri、Tailwind) | 1:1             | 画布就用同一份 HTML / CSS 渲染                  |
| React Native / Flutter / SwiftUI / Compose                            | 高精度,非逐像素 | 需要转写一次;原生阴影算法与字体渲染存在平台差异 |

## 5. 第二步:UI 框架页签

### 5.1 入口【给定】

- rail 独立入口,名称「UI 框架」(暂定),页签形式。
- 【AI补充】采用单例签:全应用只此一张,入口再点只聚焦;与概览、图谱、设置同级。

### 5.2 进入流程

1. **选平台**:电脑端 / 手机端,两者分开设计【给定】。
   - 【AI补充】平板、网页响应式放在后续里程碑:网页先按电脑端画布处理,后续加窗口宽度切换。

2. **选起点**:
   - 默认基础模板,在模板上微调【给定】
   - 空白起步,从中性默认值开始自己调【给定:从 0 创建】

3. **技术栈不在此处强制选择**,到导出时再选(第 4 节 结论)【AI补充】。

**手柄映射**【给定:拖动边、角、位置调整数值;AI补充具体映射】

| 操作                     | 对应数值                                                        |
| ------------------------ | --------------------------------------------------------------- |
| 拖组件外边缘             | 宽度 / 高度(高度通常绑定控件高度档)                             |
| 拖组件内侧的内边距手柄   | 上 / 下 / 左 / 右内边距(按住 Shift 四边同步)                    |
| 拖角上的圆点             | 圆角(按住 Shift 四角同步)                                       |

| 属性面板输入             | 以上全部 + 颜色、字号、字重、行高、描边、阴影、透明度、动效时长 |

**拖动手感**【给定:像拉窗口那样丝滑;具体参数验证后定】

- 手柄跟手,拖动中实时更新,不加缓动动画。原因:缓动会产生延迟感。
- 光标随手柄变为对应的拉伸箭头;拖动中在手柄旁显示当前数值与原值差。
- 吸附:默认按 0.125rem(2 逻辑像素)步长吸附;靠近已有变量值时轻微磁吸;按住 Alt 关闭吸附。【验证后定:步长与磁吸强度】
- 键盘微调:选中参数后方向键 ±1 步长,Shift + 方向键 ±4 步长。
- 按住空格临时显示修改前的样子,松开恢复,用于前后对比。

**共用变量的处理**【验证后定】

- 拖动的数值绑定到共用变量时,提示「该变量同时影响 N 处」,提供「改变量本身」与「只改这一处(自动新建专属变量)」两个选项。
- 默认行为由 MVP 试用后决定。

**撤销与重做**:每次改动记录「参数、原值、新值」;Ctrl+Z / Ctrl+Shift+Z。

## 6. 设计变量(Design Tokens)体系【给定:表格默认走 token 与 rem;AI补充完整体系】

### 6.1 三层结构(行业通行做法)

| 层                  | 作用                          | 例子                                         |
| ------------------- | ----------------------------- | -------------------------------------------- |
| 基础变量(primitive) | 原始数值,不带用途             | `color.blue.500 = #3b82f6`、`space.4 = 1rem` |
| 语义变量(semantic)  | 带用途的别名,引用基础变量     | `color.action.primary = {color.blue.500}`    |
| 组件变量(component) | 某组件的具体参数,引用语义变量 | `button.primary.bg = {color.action.primary}` |

改基础变量全局联动;改语义变量只影响该用途;改组件变量只影响该组件。

### 6.2 变量类别全集与默认档位

| 类别     | 包含                                                                                                                                                                                                                  | 默认档位(空白起步时的中性值,逻辑像素)                                                             |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| 颜色     | 基础色板:品牌主色、辅助色、中性灰阶(11 档)、功能色(成功、警告、危险、信息)。语义色:页面背景、表面、浮层、文字(主 / 次 / 弱 / 反白)、边框(普通 / 强)、主操作、主操作文字、悬停底、选中底、焦点环、遮罩。全部分亮暗两套 | 中性灰阶 + 一个蓝色主色                                                                           |
| 字体     | 字族(界面 / 等宽 / 标题可选)、字号阶梯、字重、行高、字间距                                                                                                                                                            | 字号 12 / 13 / 14 / 16 / 18 / 20 / 24 / 30 / 36;字重 400 / 500 / 600 / 700;行高 1.25 / 1.5 / 1.75 |
| 间距     | 内边距、外边距、组件间距统一一套阶梯                                                                                                                                                                                  | 0 / 2 / 4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 / 64                                             |
| 尺寸     | 控件高度(小 / 中 / 大)、图标尺寸、头像尺寸                                                                                                                                                                            | 电脑控件 28 / 36 / 44;手机控件 36 / 44 / 52;图标 16 / 20 / 24                                     |
| 圆角     | 无 / 小 / 中 / 大 / 特大 / 全圆                                                                                                                                                                                       | 0 / 4 / 8 / 12 / 16 / 9999                                                                        |
| 描边     | 宽度、样式                                                                                                                                                                                                            | 1 / 1.5 / 2;实线                                                                                  |
| 阴影     | 层级阴影 0~4 档(贴地 → 浮层 → 对话框)                                                                                                                                                                                 | 0 / 小 / 中 / 大 / 特大                                                                           |
| 透明度   | 禁用态、遮罩                                                                                                                                                                                                          | 禁用 0.4;遮罩 0.4                                                                                 |
| 动效     | 时长三档、缓动曲线                                                                                                                                                                                                    | 100ms / 200ms / 300ms;标准缓出曲线                                                                |
| 层级顺序 | 下拉菜单、浮层、对话框、提示气泡的叠放顺序                                                                                                                                                                            | 按此顺序递增                                                                                      |
| 焦点环   | 宽度、偏移、颜色                                                                                                                                                                                                      | 2 / 2 / 主色                                                                                      |
| 断点     | 网页响应式的宽度分界(M3 起用)                                                                                                                                                                                         | 640 / 768 / 1024 / 1280                                                                           |

### 6.3 命名与格式

- 变量层遵循 W3C 设计变量社区组格式(DTCG 2025.10,2025 年 10 月发布的首个稳定版;Figma、Penpot、Style Dictionary 均支持)。原因:导出的变量文件能直接被行业工具读取,用户不被锁定在 CodeAtlas。
- 命名用点分层级:`类别.用途.变体.状态`,如 `color.text.secondary`、`button.primary.bg.hover`。

## 8. 视觉风格预设【AI补充】

### 8.1 概念澄清

小葵在立项流程里提到「UI 大体(如版式 / 美术风格 / 框架等)」,三个词分属不同层面:

| 词       | 准确含义                                      | 在本功能中的位置                    |
| -------- | --------------------------------------------- | ----------------------------------- |

| 框架     | 技术框架(React、Flutter 等)                   | 导出目标(第 13.5 节),与视觉数值无关 |

### 8.2 风格预设清单

风格预设 = 一组全局变量的预设值(圆角、阴影、描边、色彩倾向、密度),套用后仍可逐项微调。

| 风格                  | 视觉特征                                 | 典型代表             |
| --------------------- | ---------------------------------------- | -------------------- |
| 极简中性              | 灰阶结构、细描边、低阴影、小圆角         | Obsidian、Linear     |

## 13. 导出:规格包【给定:以 AI 最可读、最能直接精准使用的数据包 + md 文档形式输出】

### 13.1 精度原理【AI补充】

AI 照做的精度,从高到低:

1. 可直接粘贴的代码(CSS 变量文件、SVG 原文、HTML 参考实现)
2. 有格式规则约束的结构化数据(JSON + JSON Schema)
3. Markdown 表格(多层信息难以表达,单位与方向易歧义)
4. 文字描述
5. 图片

## 15. 方案文件格式【AI补充】

- 后缀:自有后缀(暂定 `.uiframe`),本质为 zip 容器,与 `.sketch`、`.penpot` 等行业做法一致。M0~M1 先以文件夹形式存在,M2 启用 zip。
- 内部结构:
  - `manifest.json`:格式版本号、创建该方案的 CodeAtlas 版本、平台、风格、创建与修改时间、作者(可空)
  - `design.json`:变量与组件数据
  - `assets/icons/`:用到的图标
  - `thumbnail.png`:缩略图
- **必须带格式版本号**。原因:表格结构升级后,旧方案可自动迁移,不会打不开。

### 19.1 M0 验收标准

1. 拖动手感由小葵试用认可。
2. **规格包由功能本身导出**,不得人工修改(实测时的包由脚本手工生成,整洁度高于真实导出,第 23.3 节)。
3. 体检(第 13.7 节)零错误。
4. 按 第 19.2 节 协议,交给至少 2 个不同的 AI 实现,其中至少 1 个为命令行 agent(如 Claude Code、Devin)。原因:实测中被测 AI 为对话式,会停下追问;命令行 agent 是否同样停下尚未验证(第 23.4 节)。
5. **零问答复刻**:被测 AI 不提出任何关于规格的问题即完成实现。实测中的 4 个问题(第 23.2 节)必须全部被包内容预先回答。
6. 比对结果:位置、尺寸、颜色、圆角、字体与对照页一致;比对方式见 第 22 节 问题 19。

### 19.2 不知情 AI 实测协议【已验证:本协议在 2026-10-02 实测中执行有效】

1. 新开对话,被测 AI 不得接触原版页面或任何背景信息。
2. 只提供规格包与固定指令:「阅读 README-给AI.md 与 pages/ 下的页面规格,严格按规格实现,不要自由发挥,没写的细节请先问我。」
3. 被测 AI 提问时,只回答所问的点,不补充任何设计提示;所有提问记录为规格包缺口,修入导出器后重测。
4. 对照页由同一规格包按规格实现,与被测页在同一浏览器、同一视口尺寸、同一字体加载条件下比对。
5. 每次实测记录:被测 AI 名称与环境、提问清单、比对结果、发现的缺口,追加到 第 23 节。

### 23.3 放水条件(结果不能直接外推)
