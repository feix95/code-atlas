## 1. 块层级结构【给定,已确认】

- **顶栏是全宽「盖头」**:从窗口最左缘贯通到最右缘,位于最顶层,不被任何块截断。
- rail(图标栏)、侧栏(文件树面板)、内容区三者全部位于顶栏**之下一层**,无任何块伸入顶栏。
- 「收起侧栏」按钮位于**顶栏最左端**,不是 rail 的第一颗图标;rail 第一颗图标在其正下方、与 rail 列对齐。

## 2. 单位制与缩放模型【给定,已确认】

### 2.1 基准单位 u

- **1u = 顶栏高度 = rail 宽度**;后文一切组件尺寸均以 u 的比例表达。
- 锚定值:**1u = 4rem**(64px @100%,约 96px @150%)【按图推算,小葵已点头采纳;若视觉上偏差,只改这一个锚值全校准】。
- 换算依据:设计稿字号约 22px/1.5 ≈ 14.7px ≈ 界面字号;稿面 2312×1633 ÷1.5 ≈ 窗口基准 1540×1090。

### 2.2 比例守恒与解耦

- **唯一改变 UI 实际尺寸的旋钮 = 设置里的整体缩放(uiScale)**。所有尺寸 rem 化,`1rem = 16px × uiScale`,缩放时全部 UI 等比变化。
- **窗口尺寸同样走基准值**:窗口记忆/默认尺寸存 100% 基准值,应用时乘 uiScale——140% 时窗口物理尺寸也 ×1.4,故任意缩放档下拿尺量,比例恒等。
- **拖窗与缩放解耦**:用户拖窗口边缘只改窗口大小,UI 元素不拉伸、不重排;此时 1:16 相对窗口的比例自然漂移,属正常、不追。
- 验收不变量:同一窗口基准尺寸下,任意 uiScale 截图实测,所有标注比例恒定。

### 2.3 行业对照(参考,非规格)

| 部位 | 业内常见 @100% | 本设计 | 定位 |
| --- | --- | --- | --- |
| 顶栏/标题栏 | 32–48px | 64px | 宽松档,小葵明确嫌 40px 档太窄 |

### 3.1 对齐与分隔线【给定,实测复核通过】

- 收起钮位于顶栏,但水平方向**以 rail 中线(x=0.5u)居中**;rail 内全部按钮同一条中线居中。
- 搜索框左缘与 workspace 卡片左缘**严格对齐**(= rail 右缘 + 约 0.15u 侧栏内边距;实测两者均 x≈114)。
- **侧栏|内容区竖分隔线向上贯通顶栏**(x≈732),将顶栏分为左「导航区」/右「页签区」;**页签区起点 = 该线,首枚页签在线后约 0.3u 处开始**——此间距在侧栏收起后同样成立(图3:rail 右缘 ≈x100,首签 x≈132)【给定+实测】。
- 分屏分界线随分屏位置向上延伸至顶栏,各页签组的页签严格位于所属分屏的列内【按图推算的结构性关系】;**分屏本身 = 现有逻辑原样保留:默认左右 1:1、分界可拖动,本次不动**(图1 中分界位置只是拖拽后的某一瞬,非规格)【给定】。
- 导航组(← → ↻)位于顶栏左段、贴该分隔线左侧(图1 实测约 x480–730)【按图推算】。
- rail 按钮纵向中心距 ~1.1u;**可点击区 ~0.75u 见方、图标居中**(顶栏同制:0.6u 热区 + 0.5u 图标)【给定】;rail 图标视觉 ≈0.425u(顶栏图标 ×0.85)【给定】。

### 3.2 圆角体系【给定方法:实测聚类 + 业内档位(Fluent/Win11 规范)】

两档制,全部 rem 化随缩放等比:

| 档 | token 值 | @100% | 用在 |
| --- | --- | --- | --- |
| 控件档 | 0.25rem | 4px | 搜索框、按钮热区、徽标等小件 |
| 容器档 | 0.5rem | 8px | workspace 卡、下拉菜单、浮层、页签顶角 |

- 依据:实测卡 ~9.3px / 菜单 ~6.7px / 页签顶角 ~6px / 搜索框 ~5.3px(图1 像素 ÷1.5);Fluent 规范控件 4px、容器 8px;8px@100% 在 150% 缩放下恰渲染为 12px,与 Windows 官方 150% 圆角档一致。
- 窗口外壳圆角沿用现有 `--radius-window`,不动。
- 页签底部外扩圆角为反向造型(§5.1),不吃这两档。

### 3.3 字体体系【给定:Obsidian 官方体系照搬,rem 化】

| token | rem | @100% | 用在 |
| --- | --- | --- | --- |
| `--font-ui-smaller` | 0.75rem | 12px | 徽标、计数、说明小字 |
| `--font-ui-small` | 0.8125rem | 13px | 菜单条目、辅助文本 |
| `--font-ui-medium` | 0.9375rem | 15px | 正文、文件名、页签标题(≈图2 实测 0.95rem) |
| `--font-ui-large` | 1.25rem | 20px | 页内标题 |

- **字重阶梯**:正文 400 / 强调 500 / 标题 600 / 特粗 700;粗体在原字重上叠加(Obsidian `--bold-modifier` 思路),不重置。
- **字族**:UI = 系统字体栈(Inter → Segoe UI → 系统默认),代码 = 等宽栈,沿用 tokens.css 现有字族变量不重造。
- 依据:Obsidian 官方 CSS 变量文档(font-ui-* 固定档 12/13/15/20px + 字重 100–900 阶梯);全部 rem 化随 uiScale 等比。

### 3.4 颜色体系【给定,小葵 PS 吸管色号】

**铁律:全部颜色为不透明实色,禁止用透明度叠出近似色**——吸管读数必须等于给定色号(本应用为透明窗体,半透明叠色必然走样)。

| 槽位 | 色号 | 用在 |
| --- | --- | --- |
| 顶栏 / rail 底 | `#ededed` | 顶栏整行、图标列底色(两者同色) |
| 面板底 | `#f6f6f6` | 侧栏、文件树、workspace 卡填充 |
| 交互灰 | `#d7d7d7` | workspace 卡悬停、搜索框底、下拉菜单滚动条 |
| 正文深灰 | `#424242` | 全部按钮图标、workspace 栏文字、文件树名、**未选中页签标题** |
| 选中页签标题 | `#141414` | 仅激活页签标题(比正文更深一档) |
| 页签 / 内容面 | `#ffffff` | 激活页签与内容区同一白面 |

- **图标着色总规【给定】:全项目只有文件树列表内的 icon 保留彩色;其余一切图标(rail/顶栏/按钮/页签/菜单/概览/设置/状态)一律单色,跟随主题文字色**——浅色下 = `#424242`,深色下 = 暗色对应值(`currentColor` 体系,禁自造色)。未给 SVG 的槽位(收起钮/对话/齿轮/导航组/窗控)沿用现有图标册 lucide 描边图标。**唯一例外**:AI 状态钮三态图标(§6.1)保留状态色——绿勾/蓝弧是状态语义本身,不算「彩色装饰」。
- workspace 卡与侧栏同底,卡缘靠细边线区分【按图推算:边线色取 `#d7d7d7` 档,实现前复核】。

### 5.1 页签:完全照搬 Chrome 页签方案【给定,重点】

小葵指定:页签**完全照抄 Chrome**(附 Chrome 深色页签条悬停截图为参照)。逐条落实:

- **激活签**:底色 = 下方页面底色;底部两角**反向(外扩)圆角**与页面融合,分界线在签处断开(实测 x=850 列 y93–95 无线);文字最深、对比最强。
- **非激活签**:底色与顶栏同档(更灰),文字更浅;**底角不融入页面**——底下压着顶栏下沿的通长细线,只有顶部两角内凹圆角。
- **悬停非激活签**:底色提亮一档,**悬停时才显示 × 关闭钮**,并出系统提示气泡(Chrome 同款 title 提示)。
- **× 关闭钮**:仅**激活签常驻**;非激活签不悬停时不显示 ×(小葵据 Chrome 截图指正)。
- **相邻页签间有细缝**(1–2px 量级,不贴死)。
- **溢出**:Chrome 式等比收窄至最小宽,不出滚动条;细节按业内惯例。
- **页签严格位于所属分屏列内**,分屏分界线上延(见 §3.1);分屏默认 1:1、可拖动 = 现有逻辑不动。
- 实现提示:反向圆角用伪元素 + radial-gradient/box-shadow 或 mask(「browser tab shape」标准画法)。
- **页签条末尾不加「+」钮**【给定:VS Code 无此钮,页签由功能入口(rail/文件树)开出】。
- **打开行为【给定,现有逻辑不动】**:点文件树节点 = 同一页签内同类切换;拖放排序/分屏拖放/右键菜单/中键关闭原样。

- **pin/unpin = 单击行首 pin 图标钮**【给定,业内标准手势】;~~双击 pin~~ 手势废止(与单击进入冲突且非标)。

### 7.2 ⚠ 搜索结果清单【功能变更 · 非纯 UI · 单独施工】

小葵拍板:搜索从「修剪树」升级为**工作区内按文件名真搜**(系统文件夹搜索的 workspace 版)。**这是本文档唯一的功能变动,执行者注意:不是换皮,要动主进程与 IPC。**

**功能规格**

- **范围**:当前 workspace 根向下**深搜磁盘**——包括从未点开过、未加载过的目录(这是与旧版的核心差异);沿用扫描器忽略规则(node_modules 等照样跳过)。
- **匹配**:文件名包含关键字即命中,不分大小写(同现有规则);只搜文件名,不搜内容。
- **呈现**:搜索词非空时,**侧栏文件树区域整体替换为平铺结果清单**;清空搜索词,文件树原样回来。
- **结果行**:文件图标 + 文件名 + 所在相对路径(如 `src/domain/`);行高/交互沿用树行规格。
- **点击结果 = 打开该文件**(走现有文件预览页签逻辑)。
- **中间态**:扫描中显示「搜索中…」;零结果显示「没找到叫『关键字』的文件」。
- 旧的树内过滤(`filterTree` 原地修剪)被此清单取代;搜索仍随侧栏一起收起(结果就住在侧栏里)。
