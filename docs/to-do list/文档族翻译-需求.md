# 文档族翻译 · 需求

状态: 审查通过,实施中
范围: 在现有对照译文页上,把「翻译成…」扩到说明书类纯文本(`.txt` / `.rst` / `.adoc` / `.asciidoc`)
读者: 未读过本仓库对话的外部审查者;本文件必须自洽,不依赖聊天记录
依据: 交接文档「产品与验收契约」md 页签翻译条;核心用户见同节首条

审查时请先读第 1~~4 节(目的 / 现状 / 否决 / 方法),再对照第 5~~7 节打验收。不要把已否决的路重新推荐为本批方案,除非能证明第 4 节的否决理由不成立。

## 1. 目的

### 1.1 产品是什么

CodeAtlas 是桌面应用(Electron):打开一个项目,在文件树点文件,右侧页签里阅读。核心用户是不读代码的项目主人。基础浏览不依赖 AI;翻译是用户主动点「翻译成…」才触发的能力。

### 1.2 本批要解决的问题

用户已经能把 Markdown 说明书对照着译成另一种语言(原文在左、译文在右,按段上屏,悬停同亮、滚动对齐)。同一类「给人读的说明书」还有 `.txt`、`.rst`、`.adoc`(README.txt、Python Sphinx、AsciiDoc),预览能打开,菜单上却没有翻译。用户的需求是:这几类明显是文本文字的文件,也能走同一套对照译文,而不是去聊天里口述、也不是去翻源码注释。

### 1.3 成功长什么样

工作区里打开 `notes.txt` / `index.rst` / `README.adoc` / `guide.asciidoc`,页签右键「翻译成…」选语种后,行为与现行 md 译文页相同:原文留着、旁边出只读译文、按空行切的段逐段翻译、左右能对上。`.ts` / `.json` / `.env` 仍然没有这项菜单。md 现行行为不变。

### 1.4 非目的(防止审查走偏)

本批不是「所有能当文本打开的文件都能翻译」,也不是「做第二套翻译引擎」。源码、配置、把翻译改走自由对话,都不是本批目标。

## 2. 现状

### 2.1 现行 md 翻译(必须保持)

页签右键「翻译成…」选语种 → 原文留在原组 → 译文镜像签落到另一组(只有一组时就地向右拆) → 按块送当前配置的模型,译好一块上一块。译文只驻内存、不落盘、只读;关镜像签即取消;换工作区清空。原文与译文按块号对照。完整契约写在交接文档「md 页签翻译」条,落地时那条要改名扩写,本批不得削弱它。

### 2.2 卡点(为什么现在只有 md 能翻)

| 卡点                     | 具体表现                                                                      | 根因                                                                        |
| ------------------------ | ----------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| 菜单焊在阅读模式上       | `.txt` `.rst` `.adoc` 能预览,右键没有「翻译成…」                              | `TabBar` 用 `canReadingMode`,该函数只认 md 系                               |
| 整条链路按 Markdown 假设 | 若只放开菜单,这三样会按 md 切块、用 MiniMD 渲染、用 Markdown 提示词           | `ipcTranslate` 写死 `splitMdBlocks`;`LinkedMdView` 内部调 `MiniMD`          |
| 原文对照接不上源码档     | `.txt` 等默认是 CodeMirror 源码档,没有阅读档;镜像打开后原文仍是编辑器         | `CodePreview` 的块视图条件是 `reading && linkedMd`,`reading` 对非 md 恒为假 |
| 共用阅读门会误伤         | 若把 txt 放进 `READING_EXTS`,菜单会出现「排版显示」,`#` `*` 会被当成 Markdown | 排版显示与翻译入口共用 `canReadingMode`                                     |
| `.txt` 不全是说明书      | `requirements.txt` 是包装清单,一翻就废                                        | 摘要词条已把它当依赖清单(`src/summarizer/index.ts`),翻译菜单没有黑名单      |

### 2.3 现成可复用、本批不必重写

- 镜像签开合、分屏、取消、换工作区清空、语种名单、标题翻译 IPC:原样复用。
- 对照公式 `scrollAlign`、悬停账、阅读档 `.code-reading` 栏宽/字号/Ctrl+滚轮:原样复用。
- 模型通道、失败重试一次、剥围栏/XML 外壳:原样复用 `ipcTranslate` 的 `translateOnce` / `cleanTranslated`。
- 不引入新依赖;不新开页签品类(仍是 `kind: 'translate'`)。

## 4. 已否决的路(审查时不要翻案,除非否决理由不成立)

### 4.1 非 md 点翻译 → 自动开自由对话,把文件当附件、预置「帮我翻译成某某语」

否决。自由对话是全应用单例,现有 `openSingletonTab` 只会点亮那张签,可能把原文盖住,做不出「原文留着、旁边出译文」。附件约 2 万字截断,长文件只看得到开头;「自己翻文件」默认关。人设是讲解员,会摘要、讲课,且默认提示词「把这份文件翻译成…」容易把源码标识符也译掉。聊天气泡也没有按段对照。人手今天就能拖文件进对话自己问,菜单捷径省不下对照体验,还占用唯一对话签。

### 4.2 源码用 tree-sitter 抽注释再译、贴回

否决,本批不做。那是另一条产品:注释 vs docstring vs 字符串、贴回后语法校验、编辑器上行级对照。项目虽已有高亮注释角色(`src/highlight/index.ts` 的 `COMMENT_NODES`),但与说明书对照不是同一模块。用户已选择先做文档族。

### 4.3 把 `.txt` 等推进现有 `READING_EXTS`,零分流复用 MiniMD

否决。阅读模式与翻译入口必须拆开。MiniMD 会把纯文本里的 `#` `*` 当成标题和强调;「排版显示」也不该出现在 txt 上。

### 4.4 本批顺手收 `.html` / `.org` / `.tex` / 无后缀 LICENSE

否决。HTML 在现行切块里会整段标成不翻;后几种标记更重或没有后缀门。留待以后按文件名或新渲染器单开。

## 5. 方法(选定方案)

核心思路:不新造翻译页,不改页签模型,不接新依赖。在「谁可以点翻译 / 怎么切块 / 怎么画 / 用哪份提示词」四处做文档族分流;开签、送模型、对照公式沿用 md。

### 5.1 独立翻译门

新增「这份预览签能不能翻译」的纯函数,与 `canReadingMode` 并列,禁止合并。

- md 系:继续可翻译(行为不变)。
- 本批新增:工作区预览签,后缀 `.txt` / `.rst` / `.adoc` / `.asciidoc`(大小写不敏感),且文件名不在黑名单。
- peek 签、图片、音频、二进制、源码、配置:仍不可翻译。
- 「排版显示」继续只认 `canReadingMode`。
- `LICENSE.txt` 给人读,允许翻译。

黑名单(小写整名):`requirements.txt`、`constraints.txt`、`cmakelists.txt`、`robots.txt`;以及 `requirements-` / `constraints-` 前缀且以 `.txt` 结尾、或以 `-requirements.txt` / `-constraints.txt` 结尾的变体。

### 5.2 切块

文档族只按空行切段,每一段都当散文送模型(不再分 code/meta/frontmatter)。`.txt` 里即使出现 Markdown 围栏或 `---`,也禁止用 `splitMdBlocks` 去吞后续段落。切块函数必须纯函数、可自测;分块只由原文决定,译文回来多少段都改不了块号。有镜像时原文必须用同一份切块渲染。

### 5.3 渲染

文档族对照稿(原文有镜像时 + 译文页)走分段纯文本:保留段内换行,套 `.code-reading` 的栏宽、字号、Ctrl+滚轮。对照外壳可复用块号属性以便 `scrollAlign` 继续工作。禁止调用 `MiniMD`。`.rst` / `.adoc` 不要求译成漂亮排版,分段纯文本可读即可。关掉全部同源镜像签后,原文回到源码档编辑器。

### 5.4 提示词

仍只允许改 `src/shared/translatePrompt.ts`,仍是纯英文 XML 执行手册、不设人设。为文档族另立入口,禁止复用 `source_markdown` 标签去包纯文本。规则要点:

- `.txt`:翻译自然语言;不翻译 URL、文件路径、版本号、纯标识符。
- `.rst` / `.adoc`:同上,并保留标记、缩进、指令、角色、锚点、字面块,只译人话。
- 标题继续走已有 title 入口(不当路径,必须译成目标语)。

主进程按文件族选切块函数和提示词,不要让渲染层各写一套。

### 5.5 建议改动面(供审查估工作量,不是开工清单)

- 名单与门:共享层新纯函数(或扩 `fileKinds.ts`)+ `TabBar` 改条件;禁止改 `READING_EXTS` 来「顺便」开门。
- 切块:新纯函数 + 自测; `ipcTranslate.ts` 与译文/原文对照两侧共用。
- 渲染:对照视图增加纯文本分支,或抽「只负责块外壳、内部插不同渲染器」; `CodePreview` 在「有镜像且属文档族」时切块视图,条件不得再要求 `reading`。
- 提示词与自测: `translatePrompt.ts`、`selftest-translateprompt.mts`;菜单命名自测可扩 `selftest-translatetab.mts`。
- 契约:交接文档翻译条扩写。

## 6. 做 / 不做(实施边界)

### 做

- 工作区 `.txt` / `.rst` / `.adoc` / `.asciidoc` 预览签出现「翻译成…」,语种与 md 相同。
- 分屏、镜像、只读、内存驻留、取消、清空、标题翻译:与 md 同一契约。
- 有镜像时原文切到同一套块视图;关镜像后恢复源码档。

### 不做

- 源码、配置、`.html` / `.htm`、`.org`、`.tex`、`.csv`、`.log`、无后缀 `LICENSE` / `README` / `COPYING`(有后缀的 `LICENSE.txt` 允许翻)
- peek 签翻译
- 给这三样加「排版显示」或 Live Preview
- 译文写盘;新依赖;改走自由对话;源码注释管线

## 7. 验收标准

1. `.txt` / `.rst` / `.adoc` / `.asciidoc` 工作区预览签右键有「翻译成…」;`.ts` / `.json` / `.env` / 图片 / 音频没有;md 系菜单与译文页与改前一致。
2. `requirements.txt`、`constraints.txt`、`CMakeLists.txt`、`robots.txt` 及 requirements/constraints 变体没有「翻译成…」;`LICENSE.txt` 有。
3. 点语种后:原文留在原组,镜像签落到另一组(单组时向右拆);签脸为「文件名 · 语种中文名」。
4. 译文按段陆续上屏;标识符、URL、版本号被改成目标语算缺陷;小模型偶发漏译(该译的没译)不作为本批缺陷。
5. 悬停任一对照段,两侧同号块一起亮淡蓝底;滚动按鼠标所在段把另一侧拉到同一高度(到边夹住)。
6. 译文页有内联标题(`.md-title`,掐尾去扩展名,只读);点开头文件不摆标题。
7. 关掉镜像签后任务取消,原文恢复源码档;换工作区后译文状态清空。
8. peek 签右键仍不出现「翻译成…」。
9. 新增切块 / 名单 / 提示词自测挂进 `package.json` 的 `test` 链;现有 `selftest-mdblocks`、`selftest-scrollalign`、`selftest-translateprompt`、`selftest-translatetab` 仍绿。

## 8. 已知风险(本批接受,不要用它们推翻方案)

- 小模型可能改动 `.rst` / `.adoc` 标记:只靠提示词,不引入语法校验器。
- 对照期间原文不能当编辑器点:与 md 有镜像时切块视图同款;关译文签即恢复。
- `.rst` / `.adoc` 译文是分段纯文本,不是原格式的排版预览:本批刻意如此,避免先写两套渲染器。
