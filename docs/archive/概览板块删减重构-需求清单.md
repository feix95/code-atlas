- 只服务于概览板块的 UI、逻辑、IPC、样式、自测 → 删除。
- 被其他板块依赖的能力 → 保留; 若其宿主在概览页内, 先迁移再删。

### 锤一 · 备注编辑迁入右键菜单

目标: 备注的编辑入口不再依赖概览页, 完全在文件树右键菜单内完成。

#### 1. 菜单内联编辑

改动文件: `src/renderer/src/components/FilePathMenu.tsx`、`src/renderer/src/components/filePathMenuStore.ts`

- `FilePathNoteActions` 结构改为:
  - `hasNote: boolean`
  - `text: string`(现有备注正文, 无备注为空串)
  - `onSave: (text: string) => void`(空串表示删除)
  - `onRemove?: () => void`(保留, 供「清除备注」独立行使用)
- 点「写/编辑备注」后菜单不关闭, 该行就地切换为输入框:
  - 输入框 `maxLength` 取 `NOTE_MAX_CHARS`(100)
  - 菜单高度估算需把输入框行按实际高度计入(`clampedPosition` 的 `rows * ROW_H` 逻辑要适配), 避免贴窗口下沿时被裁切
  - 编辑态下点击菜单内部不得触发 `useMenuDismiss` 关闭
- 键鼠细则(必须逐条实现):
  - **Enter 保存并关闭菜单**。保存前先判 `event.nativeEvent.isComposing`, 中文输入法选字时按回车不得触发保存
  - **Esc 取消并关闭菜单, 不写盘**。`useMenuDismiss` 在 `document` 捕获期监听 Esc, 比输入框的 `onKeyDown` 先执行; 输入框须在捕获期 `stopPropagation`, 或由菜单在编辑态下暂停 Esc 关闭, 否则会出现「先关菜单 → 元素卸载 → 触发失焦保存」的竞态
  - **失焦保存**。失焦时若输入框为空且原本有备注, 视为取消, 保留原备注不删除
  - **删除只走「清除备注」独立行**。避免「清空内容再点外面」静默删掉备注
- 备注文本写入前做净化: 换行(`\r`、`\n`)、制表符、其余 C0 控制符一律折叠为单个空格, 再 `trim`、再按 `NOTE_MAX_CHARS` 截断(D7)。净化放在 `shared/notes.ts` 的写入路径, 保证旧存档读入时也能被清洗

#### 2. 备注覆盖悬停提示

改动文件: `src/renderer/src/components/FileTree.tsx`

- 文件行: 有备注时 `data-tip` 只取备注正文; 无备注时维持现状(引擎摘要)。
- 文件夹行: 有备注时 `data-tip` 只取备注正文; 无备注时维持现状(摘要 + 子项数)。
- 行内「有备注」小笔标(`tree-note-mark`)保持不变。

## 七、风险与注意事项

1. `src/main/ipcGit.ts` 文件名具有误导性: 它同时承载 git 与 AI 讲解两类 handler。删除时须逐个 handler 摘除, 不能按文件名整体判断。
2. `Badge` 与 `Crumb` 是两个跨文件依赖, 删 `DetailHeader.tsx` 前必须先处理, 否则 typecheck 会断。
3. `App.tsx` 中 `structure` 与 `analyzing` 生命周期不同: `structure` 要给自由对话当附件证据, `analyzing` 只服务概览。不可一并删除。
4. `selftest-journey.mts` 把「项目导览标题」当作扫描完成的信号, 这是最容易被忽略的隐式依赖, 必须重写等待条件。
5. 菜单内联输入框会改变菜单高度估算, 贴窗口下沿时须实测不被裁切。
6. `useMenuDismiss` 的 Esc 监听在 `document` 捕获期, 会抢在输入框 `onKeyDown` 之前。必须显式处理, 否则 Esc 会变成「关菜单 + 失焦保存」, 等于没取消。
7. 备注写入路径不净化换行时, 备注正文里的 `\n` 能让 tooltip 伪造出第二行。已在 D7 中处理, 实施时须同时覆盖旧存档读入。
8. 已推送的 commit 不得重写历史; 同一功能调试期不 commit, 待确认后一次性提交。
9. 本次删除顺带消除两个安全面: `src/git/index.ts` 未禁 `core.fsmonitor` / `ext-diff` / `textconv`, 恶意仓库的 `.git/config` 可借此执行任意命令; `aiExplainFile`、`aiExplainFolder`、`gitChanges` 三个接口接收渲染进程传入的 `rootPath`。删除后风险面自然消失, 无需额外改造。
