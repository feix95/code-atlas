# 关系图谱（Graph View）实施方案

> 状态: 已审阅通过，实现完成待验收。本方案取代同目录《项目关系图谱（Graph View）.md》中的旧需求表与探究表。

## 1. 定位

资源管理器的图形视图（graph view）: 数据与层级完全沿用文件树，一次只呈现一个目录层级；外观与交互手感对标 Obsidian Graph View。

- **层级导航（drill-down）**: 画布只显示「当前目录」的直接子项（子文件夹 + 文件）。单击文件夹 = 进入该目录，画布换成它的子项；不做原地展开、不做全项目平铺。
- **按需加载（lazy loading）**: 进入目录时才读取其子项；目录为扫描器未探测的 `lazy` 状态时，复用 `App.tsx` 的 `handleExpandLazy` 扫描该层，与文件树共享同一份 `ScanResult`。
- **引用关系**: 复用 `depgraph` 输出的 `DepGraphResult.edges`，不新增关系计算。

## 2. 验收标准

1. 暗色主题下，本项目任一目录的画布截图与参考图（Obsidian Graph View）并排对比，外观相似度达 80%: 深色底、灰色实心圆节点、细灰连线、节点下方小字标签、节点大小随连接数变化。
2. 交互手感与参考图一致（小葵亲手验收）: 悬停高亮、拖拽节点带弹性、滚轮缩放、拖动空白平移、缩小时标签淡出。
3. 当前层级内有引用关系的节点之间有带方向箭头的连线；无任何引用关系的文件显示为孤立节点。
4. 单击文件夹进入下一层，面包屑（breadcrumb）可返回任一上级；单击文件打开文件预览页签。
5. 亮色主题下配色跟随主题 token，无硬编码颜色。
6. `npm run typecheck` → `lint` → `test` → `build` → `test:journey` 全绿。

## 3. 画布内容规则

以当前目录 `D` 为视角:

| 元素       | 规则                                                             | 视觉                                                                                                 |
| ---------- | ---------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 文件节点   | `D` 的直接子文件                                                 | 实心灰圆；半径随「引用边数」增大                                                                     |
| 文件夹节点 | `D` 的直接子文件夹，代表其全部后代                               | 实心圆，主题强调色低饱和版；半径随后代文件数增大（开方缩放）；`lazy` 目录显示空心描边表示尚未扫描    |
| 层内引用边 | 两端都落在 `D` 内的引用，端点按「归并规则」映射到 `D` 的直接子项 | 细灰线 + 小箭头指向被引用方；多条归并为一条时线宽随条数增加                                          |
| 层外引用边 | 一端在 `D` 外的引用                                              | 外部端点映射为「外部节点」，虚线描边的幽灵节点（ghost node），标签取路径最后一段，完整路径见读屏文本 |
| 孤立节点   | 归并后无任何边的子项                                             | 同普通节点，无连线                                                                                   |

**归并规则（edge aggregation）**: 文件 `a/b/c.ts` 在视角 `D = a` 下映射为子项 `a/b`；在 `D = a/b` 下映射为文件本身。映射后两端相同的边（目录内部自引用）丢弃；相同端点对的多条边合并并计数。

**外部节点映射**: 外部端点取「它与 `D` 的最近公共祖先」下一级的路径。例: `D = src/renderer`，目标 `src/shared/types.ts` → 外部节点 `src/shared`。单击外部节点 = 导航到该目录。

## 4. 交互

| 操作                  | 行为                                                                                                           |
| --------------------- | -------------------------------------------------------------------------------------------------------------- |
| 悬停节点              | 该节点与其相邻节点、相连边高亮，其余节点和边降低不透明度；显示节点标签（不受缩放阈值限制）                     |
| 单击文件              | 调用 `openPreview(relPath)` 打开文件预览页签                                                                   |
| 单击文件夹 / 外部节点 | 进入该目录，画布过渡动画: 旧节点淡出，新节点从画布中心散开                                                     |
| 拖拽节点              | 节点跟随指针，力导向模拟重新加热（reheat），相邻节点被牵动；松开后节点回归自由                                 |
| 滚轮                  | 以指针为中心缩放，范围见 `graphConfig`                                                                         |
| 拖拽空白              | 平移画布                                                                                                       |
| 面包屑                | 画布顶部显示 `根 / a / b`，单击任一段返回该层                                                                  |
| 右上角按钮            | 「适应画布」: 缩放平移至全部节点可见                                                                           |
| 键盘                  | `Tab` 在节点间切换焦点（画布同步高亮），`Enter` 等同单击；`Backspace` / `Alt+←` 返回上一层；`Esc` 取消悬停状态 |
| 自动适应              | 每层布局首次稳定时，若有节点超出视口则自动执行一次「适应画布」；不主动放大                                     |

键盘与读屏入口: 画布旁渲染视觉隐藏的节点按钮清单（`.graph-a11y`），按钮文本描述节点类型、名称与引用数；journey 测试经此清单操作节点。

标签可见性: 缩放比例低于阈值时标签透明度线性降至 0（与 Obsidian 一致）；悬停节点及其邻居的标签始终可见。

## 5. 界面状态

| 状态                    | 表现                                                                           |
| ----------------------- | ------------------------------------------------------------------------------ |
| 引用关系加载中          | 节点照常绘制（来自扫描树），右上角显示「正在分析引用关系」；数据到达后补画连线 |
| 引用关系加载失败        | 节点照常绘制，顶部提示条显示错误信息 +「重试」按钮                             |
| 目录扫描中（lazy 目录） | 画布中央显示加载提示；失败时显示错误并保留在上一层                             |
| 空目录                  | 画布中央显示「这个文件夹是空的」                                               |
| 切换项目 / 返回首页     | 视角重置到根目录；作废进行中的请求（遵守交接文档「产品与验收契约」）           |

进入图谱页签时若 `graph` 为空且未在加载，自动调用 `handleLoadGraph`。

## 6. 技术方案

### 6.1 选型: d3-force + Canvas 2D 自绘

| 候选                      | 结论   | 理由                                                                                                                    |
| ------------------------- | ------ | ----------------------------------------------------------------------------------------------------------------------- |
| d3-force + Canvas 2D 自绘 | 采用   | 只负责布局计算，渲染与交互完全自控，是实现 Obsidian 细节（标签淡出、悬停降透明度、过渡动画）的必要条件；依赖仅 3 个小包 |
| force-graph               | 不采用 | 引入 15 个依赖；渲染风格固定，细节手感难以调到参考图水平                                                                |
| cytoscape / sigma         | 不采用 | 体量大；默认观感偏数据分析工具，与参考图差距大                                                                          |

单层节点数受目录规模限制（通常 < 200），Canvas 2D 性能充足，无需 WebGL。

**引入新依赖闸口（d3-force）**

| 维度         | 结果                                                                 |
| ------------ | -------------------------------------------------------------------- |
| 必要性       | 力导向布局算法手写易出错，布局交给成熟库；渲染自绘                   |
| 维护活跃度   | 最近发版 2023-07，未满足「近 6 个月有发版」；D3 官方维护、API 已定型 |
| 使用规模     | npm 周下载约 2100 万                                                 |
| 许可证       | ISC（宽松许可证，与 MIT 同类）                                       |
| 类型支持     | `@types/d3-force`                                                    |
| 体积与依赖树 | 依赖 d3-dispatch / d3-quadtree / d3-timer                            |
| 发布时间     | 满 7 天                                                              |

### 6.2 模块划分

| 文件                                         | 职责                                                                                                                                                |
| -------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/shared/graphView.ts`                    | 纯函数 `buildLevelGraph(tree, edges, dirRel, maxNodes)`: 输出当前层的节点（文件 / 文件夹 / 外部）与归并后的边；含归并规则与外部节点映射。不依赖 DOM |
| `src/renderer/src/graph/graphConfig.ts`      | 集中配置: 力参数（斥力、连线长度、向心力）、节点半径范围、缩放范围、标签淡出阈值、动画时长                                                          |
| `src/renderer/src/graph/useForceLayout.ts`   | 力导向模拟生命周期: 创建、切换层级时重建、拖拽时 reheat、卸载时停止                                                                                 |
| `src/renderer/src/graph/useGraphRender.ts`   | 按需 requestAnimationFrame 渲染循环: 悬停过渡、层级淡出淡入、主题变化重读颜色、首次稳定自动适应                                                     |
| `src/renderer/src/graph/useGraphNav.ts`      | 层级导航: 当前目录、进入 lazy 目录前按需扫描、返回上一层；状态 `idle / scanning / failed`                                                           |
| `src/renderer/src/graph/useGraphViewport.ts` | 视口变换（缩放 / 平移）、指针命中检测、悬停与拖拽状态；设备像素比（devicePixelRatio）适配                                                           |
| `src/renderer/src/graph/drawGraph.ts`        | Canvas 绘制: 边、箭头、节点、标签；颜色从 CSS 自定义属性读取                                                                                        |
| `src/renderer/src/components/GraphView.tsx`  | 页签正文: 面包屑、工具按钮、状态提示；组合上述 hook；替换 `TabBody.tsx` 的 `GraphPlaceholder`                                                       |
| `src/renderer/src/assets/css/graph.css`      | 图谱专用 token（`--graph-node`、`--graph-edge`、`--graph-label` 等）的亮 / 暗两套取值                                                               |

交互状态收敛为单一状态变量: `idle | hovering | dragging-node | panning`。

### 6.3 数据流

1. `TabBody` 传入 `result.tree`、`graph`、`graphLoading`、`graphNote`、`handleLoadGraph`、`handleExpandLazy`、`openPreview`。
2. `GraphView` 维护当前目录 `dirRel`（初始为根 `''`）。
3. `buildLevelGraph` 以 `useMemo` 计算当前层节点与边。
4. 进入 `lazy` 目录时先 `await handleExpandLazy(dirRel)`，扫描结果写回共享 `ScanResult`，文件树同步可见。

### 6.4 自测

- 新增 `scripts/selftest-graphview.mts`，登记进 `package.json` 的 `test` 链: 覆盖层内边、归并计数、目录内部自引用丢弃、外部节点映射、孤立节点、`lazy` 目录、根目录视角。
- `selftest-journey.mts` 增加步骤: 打开关系图谱页签 → 断言画布渲染 → 进入一个子目录 → 断言面包屑更新 → 截图存 `.planning/journey/`。

## 7. 不做的事（non-goals）

- 全项目平铺视图、原地展开子目录。
- 3D 图谱。
- 在图上编辑或手动添加关系。
- 布局持久化（与「不写入无意义缓存」契约一致）。
- 搜索与类型过滤（后续迭代）。
- CSS、Markdown 等非代码文件之间的引用识别（depgraph 当前不支持；这类文件显示为孤立节点）。

## 8. 风险

| 风险                                                         | 应对                                                                                               |
| ------------------------------------------------------------ | -------------------------------------------------------------------------------------------------- |
| 单层子项过多（如数百个文件平铺的目录）导致布局拥挤、帧率下降 | `graphConfig` 设单层节点上限；超限时按引用数排序保留前 N 个，其余归并为「其余 N 个文件」节点并提示 |
| 高 DPI 屏幕（125% / 150% 缩放）画面模糊                      | Canvas 尺寸乘以 `devicePixelRatio`；按交接文档「UI 改动自查清单」在两档缩放下验证                  |
| 用户预期落差: 部分确有关联的文件显示为孤立                   | 画布底部常驻一行说明: 当前支持识别引用的语言清单                                                   |

## 9. 实施步骤

1. 安装 `d3-force`、`@types/d3-force`。
2. `graphView.ts` + 自测（先写测试）。
3. `graphConfig` / `useForceLayout` / `useGraphViewport` / `drawGraph`。
4. `GraphView.tsx` + `graph.css`，接入 `TabBody`，删除 `GraphPlaceholder`。
5. journey 步骤。
6. 全量验证 → 暗色截图与参考图并排对比 → 交小葵验收。
